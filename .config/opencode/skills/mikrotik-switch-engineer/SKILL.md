# MikroTik и управляемые коммутаторы (сетевой инженер)

Навык для работы с MikroTik (RouterOS, CRS/CSS/SwitchOS/SwOS) и управляемыми коммутаторами, включая модели Netcraze или иные вендорные свитчи, в локальной/офлайн-среде.

## Сначала факты
- Идентифицировать устройство: вендор/модель/ОС/версия, роль, management IP, способ доступа (SSH, API, HTTP/Winbox-порт, консоль).
- Проверить доступность: `ping`, нужный порт (`22/8291/80/443` и т.д. — в рамках разрешённой LAN), текущие соседи/топологию если известны.
- Снять текущее состояние **до изменений**: экспорт/бэкап конфига, таблицы интерфейсов/мостов/VLAN/ARP/MAC/FDB, маршруты, логи/алерты.
- Не угадывать имена интерфейсов, VLAN ID, адреса и политики — сверять с инвентарём (`/root/workspace/homelab/homelab.json`, `INVENTORY.md`) и фактическим выводом команд.

## MikroTik RouterOS (типовые команды)
```routeros
/system identity print
/system resource print
/system routerboard print
/interface print detail
/ip address print
/ip route print
/ip neighbor print
/interface bridge print
/interface bridge port print
/interface bridge vlan print
/interface vlan print
/ip firewall filter print
/ip firewall nat print
/log print where topics~"error|critical|warning"
# экспорт (без скрытия чувствительных данных — осторожно с выводом):
/export show-sensitive
```
- Изменения вносить точечно; предпочтительно безопасные практики (Safe Mode при интерактивной сессии, если доступно; резервная копия `/system backup save` и `/export`).
- Учитывать различия версий (v6/v7) и платформ (bridge VLAN filtering vs switch chip VLAN на CRS).

## MikroTik SwitchOS/SwOS (CSS/некоторые CRS)
- Обычно управляется через веб-интерфейс; конфиг — VLANs, LAG, PoE, port isolation, ACL. Перед правками — сохранить/экспортировать текущие настройки (backup). Менять по одному шагу, не теряя management-доступ (не снимать свой management VLAN/untagged без плана).

## Управляемые L2/L3 коммутаторы (общий подход, в т.ч. Netcraze/другие)
- Уточнить точную модель и CLI/веб-особенности. Если модель/документация неизвестны — действовать только по фактически доступным командам/меню устройства, не выдумывая синтаксис.
- Базовые задачи: порты (up/down, speed/duplex), VLAN (access/trunk, native/PVID), LAG/LACP, STP/RSTP, DHCP snooping/DAI/port security (если поддерживается), QoS/CoS, PoE, зеркалирование портов, управление (management VLAN/IP/ACL).
- Всегда сохранять конфиг в NVRAM/startup после проверки (`write`/`save`/`copy running-config startup-config` — по вендору) и иметь путь отката.

## Безопасность и изменение сети
- **Перед изменением:** бэкап/экспорт, понимание влияния (особенно VLAN/STP/management uplink), окно/план отката.
- **Риск потери доступа:** правки VLAN/management/trunk/ACL могут отрезать устройство — делать по шагам, иметь альтернативный доступ (консоль/второй путь) когда возможно.
- Не отключать защиту без запроса, не открывать управление в недоверенные сегменты, не публиковать пароли/ключи/сертификаты/snmp-community.
- Разрушительные/рискованные действия (reset, upgrade, массовые правки, изменение uplink/management) — только с явным подтверждением пользователя.
- Работать только в рамках разрешённой сети/устройств; не сканировать и не трогать чужие сегменты.

## Офлайн-ограничения
- Не устанавливать пакеты/прошивки из интернета. Обновления RouterOS/ПО свитча — только из локально доступных файлов, по явному запросу и с бэкапом.
- Если устройство/доступ/креды отсутствуют — явно указать, что нужно от пользователя (IP, модель, способ доступа, учётные данные через секрет-хранилище, а не в чат).
